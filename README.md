# ProxiSpeakMeet

**ProxiSpeakMeet** is a browser-based geospatial virtual office. People enter a shared 2D office, move their avatars around the floor, discover nearby participants, and communicate through proximity-based WebRTC audio. Distance, direction, and room obstacles influence the local audio mix.

> **Documentation source:** `ProxiSpeakMeet-main (3).zip`, uploaded 11 November 2026. This documentation was generated by inspecting the source tree in that archive. It describes that archive—not an assumed GitHub branch or a later unprovided working tree.

## Product capabilities found in this source snapshot

- Account registration, email verification, login, password reset and authenticated profile/session lookup.
- Persistent authentication using access JWTs and rotating refresh sessions in an HttpOnly cookie.
- Authenticated dashboard with profile, room catalogue, meeting history and create/join meeting flows.
- Public and private rooms, owner-managed invitations and access revocation.
- Invite URLs that identify a room using the `room` query parameter.
- Profile options for display name, avatar shape, avatar colour and microphone preference.
- 2D virtual office, avatar movement, room geometry, obstacles and office blueprint import.
- Socket.IO room membership, presence, movement, media-state notifications and WebRTC signaling.
- WebRTC peer-to-peer audio connections.
- Web Audio spatial mixing: distance attenuation, stereo panning and obstacle/occlusion processing.
- Nearby people/peer list, connection status, audio settings and spatial audit UI.
- MongoDB persistence, optional Redis Pub/Sub and Socket.IO Redis adapter.
- Seed, spatial audit, load-test and automated test scripts.

## Quick start

Requirements: Node.js `>=18.17`, npm, MongoDB, and optionally Redis. Docker Desktop is the simplest way to start the local MongoDB/Redis services.

```bash
# From repository root
cp .env.example .env
cp client/.env.example client/.env

npm install
npm run build
docker compose up -d
npm run seed
```

Run the backend and frontend in separate terminals:

```bash
npm run dev:server
npm run dev:client
```

Open `http://localhost:5173`. The local backend defaults to `http://localhost:4000`.

For a single-origin production-style local run:

```bash
npm run build
npm start
```

Then open `http://localhost:4000`.

## Known deployment caveats from the uploaded source

1. `.env.example` documents `VITE_SERVER_URL`, while the client also has a production fallback URL. Configure the client URL deliberately for the target deployment.
2. `render.yaml` currently names a branch `arena/0db06934-proxispeak-geospatial-proximit`. Verify this is the branch you actually intend Render to deploy before using the Blueprint.
3. The supplied WebRTC configuration includes a STUN server; no TURN server configuration is present in this source snapshot. Some restrictive networks may therefore fail to establish peer media.
4. `client/src/state/ProxiContext.jsx` contains persisted meeting-intent handling, while `client/src/utils/meetingSessionStorage.js` separately defines a sessionStorage helper. Verify which path is active in the current app before changing refresh behavior.
5. A successful Socket.IO or WebRTC connection indicator does not prove that a live microphone track is enabled and audible.
6. No claim is made here that the archive's automated tests or production build have passed. Run the commands in [Testing](docs/TESTING.md) against the exact release commit.

## Support and change policy

Treat the implementation as the final authority. When changing a route, event, model field, environment variable, room permission or audio lifecycle, update the relevant documentation and tests in the same pull request. Do not put secrets in source control.
